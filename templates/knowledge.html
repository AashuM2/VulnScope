📚 Security Knowledge Base

A practical reference to the seven vulnerability categories checked by VulnScope, with examples, detection notes, and remediation guidance.

Use responsibly: Scan only websites you own or have explicit permission to test. Active checks send test requests and may create logs or trigger security alerts. Findings are indicators for review, not a guarantee that a system is vulnerable or secure.
🔐

SSL/TLS Certificate Issues

Critical

What is it?

SSL/TLS encrypts traffic between a browser and a web server. A missing, expired, or untrusted certificate means the browser cannot reliably verify the server's identity; it does not automatically mean the connection is unencrypted.

Real World Example

If a site uses plain HTTP, someone on an untrusted network may be able to read or alter traffic. An invalid certificate is a different problem: encryption may still exist, but the browser cannot reliably verify the server identity.

How VulnScope Detects It

Static

Attempts an SSL handshake on port 443. If it fails or the certificate is invalid, the vulnerability is flagged.

✅ How to Fix

Install a valid SSL certificate. Use Let's Encrypt — it's free and widely trusted.

🛡️

Missing Security Headers

High / Medium

What is it?

HTTP security headers are instructions a web server sends to the browser telling it how to behave. Missing headers leave the browser without important protections.

Headers VulnScope Checks

  • Content-Security-Policy — prevents script injection
  • X-Frame-Options — prevents clickjacking
  • Strict-Transport-Security — forces HTTPS
  • X-Content-Type-Options — prevents MIME sniffing
  • Referrer-Policy — controls how much referrer information is shared
  • X-XSS-Protection — legacy header; modern browsers generally rely on CSP and safe output encoding instead

Real World Example

A page without a suitable Content-Security-Policy may have fewer safeguards if an attacker manages to inject script content. Missing X-Frame-Options or frame-ancestors can also make clickjacking easier.

How VulnScope Detects It

Static

Reads HTTP response headers from a normal GET request and checks for selected security headers. A missing header is a hardening finding, not proof that the site is exploitable.

✅ How to Fix

Add missing headers to your server config. For Apache: Header set X-Frame-Options "DENY" in .htaccess.

SQL Injection

Critical

What is it?

SQL Injection is an attack where a hacker inserts malicious SQL code into an input field. If the website passes this input to the database without sanitization, the attacker can read, modify, or delete the entire database.

Real World Example

A login form accepts username. Attacker types: ' OR '1'='1. This makes the SQL query always true — logging in without a password.

How VulnScope Detects It

Active

Sends actual SQL payloads (', ' OR '1'='1) and checks if the response contains SQL error messages.

✅ How to Fix

Always use prepared statements and parameterized queries. Never concatenate user input directly into SQL strings.

⚡

Cross-Site Scripting (XSS)

High

What is it?

XSS occurs when a website reflects user input without sanitization. An attacker can inject malicious JavaScript that runs in the victim's browser — stealing cookies or redirecting users.

Real World Example

A search box reflects your query. Attacker types <script>alert('hacked')</script> — if unescaped, this script executes in every visitor's browser.

How VulnScope Detects It

Active

Sends XSS payloads via common parameter names and checks if the payload appears unescaped in the response.

✅ How to Fix

Sanitize and escape all user input. Use CSP headers. Never use innerHTML with untrusted data.

↪️

Open Redirect

Medium

What is it?

Open redirect lets an attacker redirect users from a trusted website to a malicious one. Users trust the original domain and don't notice the redirect to a fake site.

Real World Example

bank.com/redirect?url=evil.com takes users to a fake banking site that steals credentials — but they trusted it because it started with bank.com.

How VulnScope Detects It

Static Active

Static scans for redirect parameters. Active sends an external redirect payload and checks if the server follows it.

✅ How to Fix

Validate all redirect URLs against a whitelist. Never redirect to user-supplied URLs without strict validation.

📁

Directory Traversal

Critical

What is it?

Directory traversal allows an attacker to access files outside the web directory by using ../ sequences to navigate up the directory tree.

Real World Example

site.com?file=../../etc/passwd could expose the Linux password file if the server doesn't validate file paths.

How VulnScope Detects It

Active

Sends traversal payloads like ?file=../../etc/passwd and checks if the response contains system file content.

✅ How to Fix

Never pass user input directly to file system functions. Use a whitelist of allowed filenames and validate all paths server-side.

🍪

Cookie & Authentication Issues

Medium

What is it?

Cookies often store session identifiers. Missing security attributes can expose a session to risks, depending on the application and transport; cookie flags reduce risk but do not replace sound authentication and CSRF defenses.

Three Cookie Security Flags

  • HttpOnly — JavaScript cannot access the cookie
  • Secure — Cookie only sent over HTTPS
  • SameSite — limits cross-site cookie sending and helps mitigate some CSRF attacks

Real World Example

If a session cookie lacks HttpOnly, injected JavaScript may be able to read it. If Secure is missing, a cookie could be sent over HTTP. SameSite helps reduce some cross-site request risks, but it is not a complete replacement for CSRF protection.

How VulnScope Detects It

Static

Reads Set-Cookie response headers and checks whether HttpOnly, Secure, and SameSite attributes are present. Cookie flags are assessed in the context of HTTPS and the application's authentication design.

✅ How to Fix

Set all three flags: Set-Cookie: session=abc; HttpOnly; Secure; SameSite=Strict
